# F-13: The parse depth limit is a jq error, not a budget termination

- **Assumption** (founding §6.6, ADR-0008, GATE check 4): nesting depth is a hard budget, and
  "each budget … ends a filter as an uncatchable termination".
- **How it fails**: jq's depth limit is a parse error. On jq-ref 1.8.2, `try fromjson catch .`
  catches "Exceeds depth limit for parsing" (jq.test line 2563), and jq.test 2558–2567 build values
  10 001 levels deep without error. An uncatchable termination would fail those cases; a depth
  limit on built values would fail the others.
- **Severity**: minor.
- **Evidence**: issue #13 ADR review (adviser, jq-ref 1.8.2).
- **Change made**: ADR-0015 makes the parse depth limit an ordinary jq error whose number
  `Limits.nestingDepth` sets. Built values have no depth limit; the writer prints
  `<skipped: too deep>` beyond 10 000 levels. ADR-0016 drops `NESTING_DEPTH` from `Budget`.
  ADR-0008's budget list and GATE check 4 drop "nesting depth" (ADR-0008 amendment); founding §6.6's
  "nesting depth" reads as the reader's limit.
