# F-14: The ratchet's cadence was written two ways

- **Assumption** (GLOSSARY "Ratchet", WORKFLOW §4.6 and §6, ADR-0014 spec-gate step 4,
  `ratchet/README.md`): the verifier regenerates the ratchet once per spec, in the spec gate.
- **How it fails**: `.claude/skills/run-spec/SKILL.md` (step 4) regenerates it after every merge. With
  once per spec, a ticket that breaks a case an earlier ticket of the same spec made pass is neither
  ratcheted nor required, so it shows only at the spec gate.
- **Severity**: minor.
- **Evidence**: issue #15 round 1 (designer conflict C1, confirmed by the adviser).
- **Change made**: ADR-0020: oracle pass lists after every merge (`regen --oracles`), coverage,
  mutation and bench once per spec (`regen --all`). WORKFLOW §4.6 and §6, the glossary and
  `ratchet/README.md` follow.
