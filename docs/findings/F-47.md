# F-47 — `keepsArgs` is declared per native in the binder until spec 3 moves it onto `Operation`

- **Assumption** (ADR-0005 "`Operation` fixes …", amended by ADR-0022; ADR-0034 "the other
  ADR-0005/0009 facts join with their first user"): `keepsArgs` is a field of `Operation`, read on
  the IR by spec 3's `keepsArgsIsSound` and its in-place licence.
- **How it fails**: #72 is the first ticket to know each native's `keepsArgs`, but nothing in 2a reads
  it. `Operation` is still `Operation(name, CallForm)` (ADR-0034), and one `Operation` can serve
  several names: `Basics.TOSTRING` is the same `TextFormat` operation `@text` uses, and only the
  native `tostring` declares `keepsArgs`. Declaring it on `Operation` in #72 would change a record
  every lowering builds, for a field with no reader.
- **Severity**: minor
- **Evidence**: review of #72 at 932b36a; `Binder.Native(name, arity, keepsArgs)`
  (jq-core `internal/parse/Binder.java`), pinned by `NativeKeepsArgsTest`.
- **Change made**: in 2a, `keepsArgs` is declared on `Binder.Native`, one value per native name, and
  pinned by `NativeKeepsArgsTest`. Its first reader is spec 3's `keepsArgsIsSound`: that ticket moves
  it onto `Operation`, so the IR carries it as ADR-0005 says. An operation shared by several names
  (`TextFormat` for `tostring` and `@text`) then takes the conservative value, `true` if any of its
  names keeps an argument, or is split into separate operations. No analysis in 2a reads
  `keepsArgs`. ADR-0005's status line names this finding.
