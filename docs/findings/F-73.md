# F-73 — NONFINITE is never written

- **Assumption**:
  - ADR-0002: a number entry's span holds "4 flags (FITS_LONG, CANONICAL, NONFINITE, one spare)".
  - ADR-0012: "NONFINITE: the literal is NaN or ±Infinity", every spelling jq accepts and "overflow
    past decNumber's exponent limit (`10E999999999`)".
- **How it fails**:
  - An overflow can be a strict token: `1e1000000000` is strict JSON, and jq-ref prints it
    `1.7976931348623157e+308` (P3). To set the flag, the fast path would have to weigh every
    exponent.
  - The flag buys nothing. Every NaN and Infinity spelling is a lenient token. An overflow needs
    an exponent, since a token holds at most 2^24−1 bytes (ADR-0002). So none of them is CANONICAL,
    and each is decoded at access anyway.
- **Severity**: minor (cost in the fast loop; no value changes).
- **Evidence**: spec 5 grilling round 1, question 5; P3.
- **Change made**:
  - NONFINITE becomes a reserved bit that no reader writes; a NaN or Infinity literal is found when
    its token is decoded.
  - ADR-0002 and ADR-0012 are amended. On the adviser's list for the owner (2026-11-16).
