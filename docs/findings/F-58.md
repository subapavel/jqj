# F-58 — The compile-mode oracle gains a `trampoline` run

- **Assumption**:
  - ADR-0020 "The compile-mode and backend oracles": an optimised, a conservative and a copy-only
    run; the `compile.txt` modes are `conservative` and `copy-only` (ADR-0023).
  - GATE check 2, "Compile modes": "the optimised, the conservative and the copy-only run agree".
  - ADR-0018: the conservative compile "has no tail calls, so its deep-recursion cases run on the
    trampoline".
- **How it fails**:
  - Only a case deep enough to pass U reaches the driver, and most cases are shallow.
  - ADR-0046 gives each of the 20 body kinds a resumable heap form. A heap form that only deep
    cases reach would be checked by a handful of cases, and a wrong one would pass every oracle.
- **Severity**: major (20 heap forms with almost no oracle).
- **Evidence**: spec 2b grilling round 1, M3; ADR-0046.
- **Change made**:
  - A third compared run, after the conservative and copy-only ones, in mode `trampoline`: the
    conservative compile with `stackBytes` 0, so `U_f ≤ 0` and main and every body run on the
    driver. Like the others it uses `Limits.embedded()` with no deadline and no regex match time
    (ADR-0020, #60).
  - Its passing ids are ratcheted in `compile.txt` under mode `trampoline`.
  - It runs wherever the conservative run does: the ticket gate's step 1 (F-46), after every merge
    (F-29) and the spec gate. A case that ends in a termination under it is left out, as under
    copy-only.
  - It is the red of the heap-forms ticket. Its added time in gate step 1 is not measured yet.
  - ADR-0020 and GATE check 2's mode list are amended. The mode list is on the adviser's list for
    the owner (2026-11-16).
