# F-56 — Cardinality "one" and "at most one" end at their result

- **Assumption**:
  - ADR-0007 "Cardinality": "An error or a break is not a result", and "'Exactly one' promises one
    result unless an error or break ends the node, so a backend reads it without testing."
  - ADR-0008: a value form "for cardinality one or at most one".
  - ADR-0006's tail condition: "every left context on the way yields at most one result".
- **How it fails**: by that wording, `(1, error("x"))` and `(1, (repeat(1)|empty))` each give exactly
  one result, yet both keep running after it. A value form must hand back its one result, so it
  either runs the rest first or drops it; a jump drops it. jq-ref:
  - `[limit(1; (1, error("x")) | .+1)]` → `[2]` (running the rest first would raise `x` instead);
  - `first((1, (repeat(1)|empty)) as $x | $x)` → `1` and terminates (running the rest first would
    never return);
  - `def f: if .>3 then . else ((.+1), error("x")) | f end; 0|f` → `4`, then error `x`, rc 5 (a tail
    jump would drop the pending errors).
- **Severity**: major (an over-claimed cardinality gives a wrong value; ADR-0007's ADR-0022
  amendment).
- **Evidence**: spec 2b grilling round 1, M1 (the jq-ref probes above).
- **Change made**:
  - "Exactly one" and "at most one" also promise that nothing runs after the result; a node that
    may run on is "many".
  - The three cases are required differential cases of the cardinality, value-form and tail-call
    tickets.
  - ADR-0007 (cardinality), ADR-0008 (value form) and ADR-0006 (tail condition) are amended, and
    the glossary's Cardinality follows.
