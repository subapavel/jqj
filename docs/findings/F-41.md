# F-41 — Spec 2a inlines definitions in the resolver, before any function list exists

- **Assumption** (ADR-0006): every `def` is lifted into the program's function list, and the passes run resolve → inline and specialise → fold.
- **How it fails**: spec 2a compiles no recursion, so every call that compiles is inlined. A `Call` node, a function list and an IR inliner would have no surviving user in 2a; their backend arms would be dead code under PIT. Each copy would also need its slots renamed in the IR.
- **Severity**: minor. The IR after inlining is the same, and no observable behaviour changes.
- **Evidence**: #70 designer draft (2026-11-13), R1.
- **Change made**: ADR-0040. jq-core's Binder holds the function table, which is the "lifted" list in 2a. The Resolver inlines every non-recursive call as it lowers, and a call into a recursive group is a Stub. 2b introduces `Call` and the IR function list with their first user and re-checks the pass order of ADR-0006 then.
