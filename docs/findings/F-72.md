# F-72 — `--stream` has its own error texts: `stream_token` is a second state machine

- **Assumption** (ADR-0015): "A Java translation of `jv_parse.c`'s token and state machine then
  re-reads" a malformed document; "`--stream`: its own tokenizer, no tape".
- **How it fails**:
  - Under `--stream` jq parses with `stream_token`, a second state machine with its own texts. Of
    20 malformed inputs probed, 8 give another text under `--stream`: `{"a":}` → "Unmatched '}'"
    against "Missing value in key:value pair". The replay's texts cannot give them, and neither can
    a tokenizer written from behaviour.
  - `--stream` has no depth limit: 20 000 open brackets end in "Unfinished JSON term at EOF".
- **Severity**: major (GATE check 3 asks for jq's message in every mode).
- **Evidence**: spec 5 grilling round 1, question 3 (jq-ref 1.8.2; `jv_parse.c` at the tag).
- **Change made**:
  - One translated file, `JvParser`, with a replay mode and a stream mode. `--stream` never runs
    the fast reader. Events before an error are emitted (P5: `[1,[2` → `[[0],1]`).
  - `NOTICE` lists `JvParser` (`jv_parse.c`). ADR-0015 is amended.
