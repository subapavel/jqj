# F-7: `//` catches no error

- **Assumption** (founding architecture §8): "`?` and `//` call non-throwing variants".
- **How it fails**: jq-ref 1.8.2 builds `//` from a FORK that re-raises on backtrack
  (`gen_definedor`), so an error on its left propagates. `[error("x") // 1]`,
  `[1 | .a // 2]` and `[(1, error("x"), 2) // 3]` each exit with rc 5 (observed by the grilling
  adviser on #7).
- **Severity**: minor.
- **Evidence**: issue #7, round 1 comment.
- **Change made**: ADR-0008 gives `//` an empty catch set. Only `?` uses quiet variants.
