# F-74 — Under `--seq` a document cut by RS vanishes only after whitespace

- **Assumption** (ADR-0015, "Input stream and modes"): under `--seq` "a cut document followed by RS
  vanishes without a message".
- **How it fails**: jq's `scan` handles RS before every state, strings included.
  - `\x1e[1\x1e2` → "jq: ignoring parse error: Truncated value at line 1, column 4".
  - `\x1e"a\x1eb"` → "Truncated value at line 1, column 4", then "Invalid numeric literal at line
    1, column 6 (need RS to resync)".
  - Empty input also prints an ignored error, rc 0.
  - Only a cut after whitespace vanishes without a message.
- **Severity**: minor (stderr under `--seq`; GATE check 3's resynchronisation case).
- **Evidence**: spec 5 grilling round 1, A2 (jq-ref 1.8.2; `jv_parse.c` at the tag).
- **Change made**:
  - `--seq` texts come from `JvParser`; the RS split stays outside the fast loop.
  - ADR-0015 is amended. On the adviser's list for the owner (2026-11-16).
