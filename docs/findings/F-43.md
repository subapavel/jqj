# F-43 — Loops need a jq null for an empty state, and range's end is read once

- **Assumption** (ADR-0041):
  - `reduce` lowers to `Reduce(I, s, bindP(SRC, Advance(s, U)))`, and its slot's null is the value U sees after an empty update.
  - `range/2` binds both bounds.
  - A Many never writes its args (the Many javadoc since #63).
- **How it fails**:
  - **The empty state is not a jq value.** query-core's empty slot is Java null, which is not a jq value. On jq-ref, `reduce (1,2) as $x (0; empty)` gives `null`, and foreach's next update after an empty one sees `null` (recorded: `reduce/foreach-update-empty-then-next` gives `[[null,3]]`). Without a mapping, 4 required #69 cases crash with an NPE or a MatchException.
  - **The end is re-read at every step.** A NumberView computes its double on each read (ADR-0012), so a range whose end is a 1 MiB token pays O(token) per tick. On 108c4d3, `reduce range(0; .) as $i (0; . + 1)` over `100000.` plus 2²⁰ zeros timed out at 5 s; jq-ref takes 0.05 s.
- **Severity**: major for the null state (wrong results); major for range (one tick buys unbounded work, ADR-0008).
- **Evidence**:
  - #69, the required cases `reduce/update-empty` and others;
  - RangeTest.theEndIsReadOnceWhenTheRangeStarts (red on 108c4d3, green on fd06fb7);
  - the #69 standards review at fd06fb7.
- **Change made** (#69):
  - The jq-core operation `_state` maps the slot's Java null to `null`, for the update's input and for the reduce output.
  - `Range.first` reads the end once and stores it in its args array.
  - The Many contract now allows `first` to replace an argument in the array its call site allocates for each loop.
  - ADR-0041 is amended in the same merge.
