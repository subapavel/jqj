# F-46 — The #70 regen ratcheted compile-mode passes that held only through a compile error

- **Assumption**:
  - A ratchet entry records a case that passes its oracle, and that pass is evidence about the property the oracle checks.
  - The ticket gate catches a ratchet regression before merge.
- **How it fails**:
  - At #70, a call to a builtin outside the four-entry native table was jq's compile error `length/0 is not defined`, rc 3 (observed on the #70 tip 11bd682: `jqj 'length'` and `jqj '{(.): length}'`).
  - The compile-mode oracle compares the conservative and optimised runs, and both ended with that same rc 3. So the regen after #70 (8bd312b, compile +2722) ratcheted many cases whose filters never compiled. The property the oracle checks (both modes agree on the result) was never exercised for them.
  - #71 does what spec story 41 and ADR-0042 ask: an unbuilt builtin is now a Stub. The compile-mode oracle rules a Stub on either side FAIL (CompileModeRunnerTest.aStubOnEitherSideFails). After the #71 merge f5e4305, `after-merge.sh 71` fails: 2 234 of 5 767 compile-mode cases fail.
  - The Stubs that cause them, in log lines (each failure appears twice): path/1 1240, length/0 828, tojson/0 630, recursive r/2 430, tostring/0 384, type/0 348, `_match_impl/3` 98, contains/1 46, and others.
  - The ticket gate did not see this, because its compile step is NOT_RUN at ticket level (F-27). Only after-merge runs `-Pcompile-oracle`.
  - `ratchet.java regen --oracles` refuses a drop, and CLAUDE.md forbids deleting a ratchet entry to go green. The integration branch therefore cannot regenerate the ratchet after #71.
- **Severity**: blocking for Spec 2a. The integration branch fails its after-merge verify.
- **Evidence**: `/home/user/jqj/.logs/71-after-merge.log` and `71-after-merge-verify.log` (line 589 onward); ratchet/oracle/compile.txt at 8bd312b; differential-interpreter.tsv at 07162ac, which shows the same ids as FAIL "jqj ended with a Stub" and not ratcheted in differential.txt.
