# F-34 — The spec-gate PIT is measured mid-spec on spec 2a

- **Assumption** (F-28 "Spec-gate PIT"): the 45-min target is checked when a spec gate measures it,
  alone on `claude-cloud-4vcpu`; only then does ADR-0020's fallback (seed grouping) apply.
- **How it fails**: an extrapolation from spec 1 (424 s per 1000 passing seeds at 661 mutants, about
  24 min at spec 1's gate) puts spec 2a's spec-gate PIT over 45 min. Measured only at the gate, the
  seed-grouping ticket would land after 2a's last ticket.
- **Severity**: major (the nightly has a 60-min timeout).
- **Evidence**: spec 2 grilling round 2, Q5 (owner yes, 2026-11-12).
- **Change made**: the verifier dispatches `nightly.yml` (`workflow_dispatch`) on 2a's integration
  branch once about half its class-C tickets have merged. Over 45 min or a time-out applies F-28's
  fallback at once, by a finding, with no owner round. Whether a dispatch on a branch ref works is
  settled by the first dispatch. F-28 is amended to point here.
- **Followed by**: F-51 (the dispatch was not made on 2a; the spec gate's PIT measured it).
