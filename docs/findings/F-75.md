# F-75 — `-R` decodes UTF-8 per read block, not per line

- **Assumption** (ADR-0015): "`-R`: each line is a built string, LF stripped, CR and NUL kept,
  invalid UTF-8 replaced; `-Rs` is one string".
- **How it fails**: jq 1.8.2's `util.c` calls `jv_string_sized` on each read block, so invalid UTF-8
  is replaced per block. A sequence cut by a block's end takes the block's last bytes (F-26). For
  `A E2 z z` with E2 at offset 4089 of a line, jq-ref prints `A�z`; on a short line it prints
  `A�zz`. 2 018 of 9 304 probed (bytes, offset) pairs differ this way. A JSON string does not.
- **Severity**: minor (invalid UTF-8 within a few bytes of a block's end).
- **Evidence**: spec 5 grilling round 1, A1 (jq-ref 1.8.2; `util.c` at the tag).
- **Change made**:
  - `-R` and `-Rs` decode each read block on its own, as jq does. jqj copies a quirk that loses a
    byte; decoding the line whole would be a `DEVIATIONS.md` row instead.
  - ADR-0015 and the glossary's "Read block" are amended. On the adviser's list for the owner
    (2026-11-16).
