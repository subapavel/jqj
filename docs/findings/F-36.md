# F-36 — "A run under 4096 ticks never reads the clock" cannot hold with a deadline from begin

- **Assumption** (ADR-0030): the deadline counts from `begin`, and a run under 4096 ticks never
  reads the clock.
- **How it fails**: counting from `begin` needs one clock read there; the two sentences cannot both
  hold.
- **Severity**: minor (wording; the intent, no clock read per tick, is kept).
- **Evidence**: #59 implementer hand-back, `RunState.java` (`begin` reads `System.nanoTime()` once).
- **Change made**: ADR-0030 now says such a run reads the clock once, at `begin`, and never checks
  the deadline.
