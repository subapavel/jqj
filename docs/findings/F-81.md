# F-81 — ADR-0017's module loader cannot resolve jq's modules

- **Assumption**:
  - ADR-0017 "Host SPI": `interface ModuleLoader { Optional<String> module(String relPath,
    JqObject meta); Optional<byte[]> data(String relPath, JqObject meta); default List<String>
    searchList(); }`, with "the `search` metadata reach the loader untouched".
  - ADR-0017 "The command-line host": "File loader: `-L` paths, else `["~/.jq",
    "$ORIGIN/../lib/jq", "$ORIGIN/../lib"]`, plus `~/.jq` as an include file when it is a file."
- **How it fails**:
  - jq 1.8.2's `linker.c` resolves a relative `search` against the importing module's own
    directory, and the main filter's against the program origin. The loader is never told who
    imports, so it cannot do the same. `tests/modules/c/c.jq` imports `d` and `e` with
    `{search:"./"}` and `{search:"./../lib/jq"}`, so jq.test 1904 and 1908 cannot pass as the SPI
    stands (jq-ref: `-L m 'import "c" as foo; [foo::a, foo::c]'` → `[0,"acmehbah"]`).
  - An entry that is exactly `"."` is the working directory, not the importer's directory (jq-ref:
    `sub/s.jq` importing `"z"` with no `search` gets the working directory's `z.jq`;
    `{search:"./"}` gets `sub/z.jq`).
  - The SPI has no name for a loaded module, so the engine cannot print jq's "circular import of
    <name>", the module's error blocks or `$__loc__.file`. It has no way in for `~/.jq` (it binds
    below every import and above the prelude), no program origin or jq origin for
    `get_prog_origin` and `get_jq_origin`, and no rule for the `optional` and `raw` metadata.
  - The validated paths lack jq's "Module path contains a NUL byte".
- **Severity**: major (check 1's module cases cannot pass, and an owner-accepted SPI changes).
- **Evidence**: spec 7 grilling round 1, questions 2–4 (`docs/wayfinder/spec-7-grilling.md`),
  proposed by the grilling-adviser for the owner under the delegation of 2026-11-14; jq-ref 1.8.2
  probes P1–P7 and the architect's re-run; jq 1.8.2's `linker.c` and `main.c`.
- **Change made**:
  - ADR-0017 gains "Amendment (spec 7 round 1; F-81)": `module` and `data` take the importer's
    name and return `record ModuleSource(String name, byte[] text)`; the loader gains `home()`,
    `programOrigin()` and `jqOrigin()`; the engine names, caches and validates modules, reads
    `optional` and `raw`, includes the home module and asks `modulemeta`'s module with the search
    list. Its second part, "The command-line host", puts linker.c's search rules in jq-cli's
    `FileModuleLoader`, which is not exported.
  - ADR-0013 and ADR-0020: `Invocation` gains `String origin`, the jq origin.
  - GLOSSARY: "jq module", "Home module", "Program origin", "jq origin".
  - DEVIATIONS: `modulemeta` on a module that does not parse; the jq origin.
  - On the adviser's list for the owner (2026-11-16).
