# F-65 — `StrictMath` is not jq-ref's libm, and jq-ref's own digits vary with the CPU

- **Assumption**:
  - CLAUDE.md and GATE check 2: the reference jq binary decides what a filter does, and a
    differential case matches its stdout byte for byte.
  - Spec 4's draft, question 3: a computed math builtin uses `StrictMath` where a probe (P3) shows
    identity with jq-ref, and gets a row elsewhere.
- **How it fails**:
  - A (12 000 inputs): `StrictMath` differs from jq-ref on all 17 functions tried: `log1p` 3,
    `tanh` 5, `sin` 424, `exp` 855, `atan2` 2 164, `cbrt` 5 527, all within 2 ulp but one `cbrt`.
    `27|cbrt` → `3.0000000000000004` on jq-ref. "Where P3 shows identity" holds nowhere.
  - jq-ref has no single set of digits to match. A: its strings name glibc and GCC 13.3.0, and
    under `GLIBC_TUNABLES=glibc.cpu.hwcaps=-FMA,-FMA4,-AVX2_Usable,-AVX2` it changed 11 of 9 000
    `sin`, 8 `sinh`, 6 `atan2`, 5 `exp` and 3 `pow` results on this machine.
  - jq's own tests do not pin these digits: jq.test rounds every transcendental it checks
    (`cos * 1000000|floor / 1000000`, lines 847–857).
  - glibc is LGPL, so translating it cannot supply the digits either.
- **Severity**: major (36 builtins cannot agree byte for byte with jq-ref on every machine).
- **Evidence**: spec 4 grilling round 1, question 3 (`docs/wayfinder/spec-4-grilling.md`).
- **Change made** (spec 4, ADR-0051):
  - The 25 exact builtins keep jq-ref's bits and its x86-64 conversions.
  - The 36 computed ones print jqj's own last digits, the same on every platform:
    - `StrictMath`, never `Math`, for the 18 it has;
    - definitions over `StrictMath` for 6;
    - Arm's `erf`, and for the other 11 published formulas until the owner answers issue #105.
  - `DEVIATIONS.md` gains one section, "libm last digits", for the 36, each row with its measured
    ulp bound. A JUnit test holds each function to its bound against jq-ref on a recorded sample.
  - `builtins-math-v1` prints a computed result only through exact functions (ADR-0020's spec-4
    amendment), so its cases agree with jq-ref byte for byte.
