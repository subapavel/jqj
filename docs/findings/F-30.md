# F-30 — U is calibrated in spec 2 without path-mode `..`; spec 3 re-runs it

- **Assumption** (ADR-0011 "U is a constant per release"; its ADR-0018 amendment): one calibration
  test, run on the interpreter in spec 2, covers the T, E, M and N shapes, a wide body, a closure
  chain, the nested-driver shape and path-mode `..` on a 10 000-deep document.
- **How it fails**: path mode (ADR-0010) arrives in spec 3 (ADR-0023), so spec 2 cannot run the
  path-mode shape. Waiting for spec 3 would ship spec 2's trampoline threshold uncalibrated across a
  spec gate.
- **Severity**: minor.
- **Evidence**: spec 2 grilling round 1, Q7 (owner yes, 2026-11-12).
- **Change made**: spec 2 (its second half) calibrates U over every ADR-0011 shape except path-mode
  `..`, with value-mode `..` on the 10 000-deep document included. Spec 3's path-mode ticket adds
  the path-mode shape and re-runs the calibration; U may only fall, as with ADR-0018's re-run for
  bytecode. ADR-0011 is amended to point here.
