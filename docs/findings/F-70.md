# F-70 — `ltrimstr`, `rtrimstr` and `trimstr` give jq's paths; spec 3's P6 row is for `trim`, `ltrim` and `rtrim`

- **Assumption** (spec 3 grilling, P6 "DEVIATIONS, not conformance"):
  - On jq-ref, `path(.k|F)` keeps the path for `ltrimstr`/`rtrimstr`/`trimstr`/`ltrim`/`trim` when
    they leave a string unchanged.
  - In jqj each is NONE and raises "Invalid path expression with result …", and each gets a new
    DEVIATIONS row.
- **How it fails**:
  - In jq 1.8.2, `ltrimstr`, `rtrimstr` and `trimstr` are prelude definitions whose body is `.` or
    a slice. jqj's path mode follows them as jq does and gives jq's paths with no row.
  - A: `{"k":"xy"}|[path(.k|ltrimstr("z")), path(.k|rtrimstr("y")), path(.k|trim)]` →
    `[["k"],["k",{"start":null,"end":1}],["k"]]`. Spec 3's P6 also recorded
    `{"k":"xy"}|path(.k|ltrimstr("x"))` → `["k",{"start":1,"end":null}]`.
  - Only the C natives `trim`, `ltrim` and `rtrim` keep a path in jq, through value identity
    (`path_intact` calls `jv_identical`), which jqj does not have (ADR-0007).
- **Severity**: minor (three rows that would have described no difference).
- **Evidence**: spec 4 grilling round 1, M7; spec 3 grilling, P6 (`docs/wayfinder/`).
- **Change made** (spec 4):
  - Spec 3's P6 list is read through this finding: its row names `trim`, `ltrim` and `rtrim` only,
    under `DEVIATIONS.md` "Path expressions accept only navigation".
  - The three prelude definitions get matching differential cases, the A filter among them.
  - The natives' row comes with the natives, in spec 4's strings ticket, which also declares their
    `keepsArgs`.
