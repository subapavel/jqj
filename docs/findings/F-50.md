# F-50 — A number token's double is re-scanned with no tick

- **Assumption** (ADR-0008, "Every native loop whose length depends on the data charges ticks
  against the step budget, per element or per KiB"): every data-length loop is charged.
- **How it fails**: `NumberView.doubleValue` (`jq-core/.../internal/value/NumberView.java:21`) scans
  the whole token, up to `Tape.NUMBER_LENGTH` (16 MiB), on every call, with no tick; Equality's
  exact path does the same. Compares, arithmetic and `range` call it once per use, so a filter that
  reuses one long token many times does uncharged work proportional to the token's length each time.
- **Severity**: minor (bounded by the token limit; no crafted n² in 2a's tests).
- **Evidence**: #66 and #69 closing comments; spec 2a review (#56, reviewer-spec).
- **Change made**: none in 2a. Ticket #97 decides between a tick of max(1, KiB) per scan and a double
  parsed once per token, under ADR-0008. ADR-0008 points here.
