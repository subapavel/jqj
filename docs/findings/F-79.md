# F-79 — `reads` has two meanings, so every path native would read input

- **Assumption**:
  - Spec 3's ticket approval, item 2, and the 3a tickets S3a.2 (#154) and S3a.3 (#155): `reads`
    is true for getpath, setpath, delpaths, `debug` and `stderr` ("shares storage with its
    input").
  - F-77, ADR-0007 and S5a.6 (#144): `reads` is the fact that an operation reads the input
    stream, and "may read input" is computed from it.
- **How it fails**:
  - Left alone, every `del`, `pick`, `tostream` or `debug` is a reading node, so `.items[] |
    del(.a)` reads whole (jq-ref: `{"b":2}`) and each such node becomes a hold site.
  - In #152–#168 only #154 and #155 give the fact a value.
- **Severity**: major (two published 3a tickets would build the wrong fact, and spec 5b's hold
  and root-use analyses would treat path natives as reads).
- **Evidence**: spec 5 grilling round 2, gap A (`docs/wayfinder/spec-5-grilling.md`, "Round 2"),
  proposed by the grilling-adviser for the owner under the delegation of 2026-11-14.
- **Change made**:
  - Spec 5's meaning stands: `reads` on an Operation means it reads the input stream, and only
    `input` sets it. The five natives have `reads` false.
  - GLOSSARY "Operation": "… its `Facts` its path rule, whether it is pure, whether it reads the
    input stream (`reads`; only `input`), and whether it keeps an argument (ADR-0048, F-79)."
  - ADR-0005 "`reads` (input)" → "`reads` (the input stream)".
  - Spec 3's ticket approval item 2 (`docs/wayfinder/spec-3-grilling.md`) → "`keepsArgs` is true
    for getpath, setpath, delpaths, `debug` and `stderr`; `reads` is false for all five (F-79)".
  - The #154 and #155 bodies say `reads` false (on GitHub, before a writer takes S3a.2 or S3a.3).
    On the adviser's list for the owner (2026-11-16).
