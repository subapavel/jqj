# F-42 — The resolver lowers a long path chain by Java recursion

- **Assumption** (ADR-0011, ADR-0034): the compiler is bounded by the parse depth (`Parser.MAX_DEPTH`, 512), so lowering cannot overflow the stack.
- **How it fails**: a postfix chain such as `.a.a.a…` is not nested in the parse depth sense, but `Resolver.lower` and `Resolver.after` call each other once per step. On the test thread, 21 844 steps end in a StackOverflowError. jq-ref accepts that chain and rejects 21 845 with "function compiled to 65537 bytes which is too long".
- **Severity**: major (an untrusted filter crashes the compiler instead of getting a clean error).
- **Evidence**: #70 red, `LongPathChainTest` at 0d4ad34.
- **Change made**: #70 lowers path chains with a loop. Chains past jq's bytecode limit compile in jqj; DEVIATIONS gets a row beside "Long comma chains".
