# F-19 — Tooling before every class-C ticket leaves the runners without an API and the measurements without passing cases

- **Assumption** (ADR-0023 "Specs in build order" 1, "Gate rules decided here"; ADR-0014 "The
  ticket gate"; ADR-0020 "Oracles"; `docs/GATE.md` spec table row 1): the tooling tickets come
  first and block every class-C ticket, and they measure every ticket-gate step, the fallbacks'
  targets and the PIT cost per 1000 seeds.
- **How it fails**: the jqtest runner and the bench module compile against the public API, which
  `AGENTS.md` makes class C; and while every body is a stub no case passes, so a gate step, the
  three-in-parallel timing and PIT per seed measure nothing.
- **Severity**: minor.
- **Evidence**: spec 1 grilling, round 1 (designer draft, grilling-adviser evaluation; owner yes to
  questions 2 and 3, 2026-11-11).
- **Change made**: the API slice is one class-C ticket blocked only by the build ticket; every
  other class-C ticket stays blocked by all tooling tickets. The tooling tickets measure only what
  needs no passing case (parallel builds, recording and verify per 1000 seeds). Spec 1's last
  ticket (class A, blocked by the last class-C ticket) measures ticket-gate steps 1–2 alone and three
  at a time and PIT per 1000 passing `values-v1` seeds, or on the seeds that pass if fewer, into
  `bench/RESULTS.md`. ADR-0023, ADR-0014, ADR-0020 and `docs/GATE.md` amended.
