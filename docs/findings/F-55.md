# F-55 — U is derived per filter and run, against ADR-0011's "U is a constant per release"

- **Assumption** (ADR-0011): "U is a constant per release, set by a calibration test". That test
  runs "cold and warm, on stacks of 512 KB and one other size". A host's declared stack bytes give U
  "after taking off a measured fixed reserve".
- **How it fails**:
  - The stack bytes are set per run: `Limits` can be overridden per run through `RunOptions`
    (ADR-0017), so no U can be fixed before the run starts.
  - A filter's own nesting before its first call uses the same stack. A constant U leaves no room
    for a body nested deeper than the calibration shapes. ADR-0011 found the same failure for a
    fixed K ("a wide body overflows before K").
  - "Cold" was not one column. The 512 KiB depth edge moved with the JIT tier (F-49: about 832 B of
    frames per level under C1) and with an agent's frames (F-44). So a warm or in-suite column
    overstates U for a host's cold JVM.
- **Severity**: major (a run would end at the stack backstop where the trampoline should take over).
- **Evidence**: spec 2b grilling round 1, Q6; F-44; F-49; ADR-0011's considered options.
- **Change made** (ADR-0046):
  - The release constants are the bytes per unit `b` and the guard reserve. Each is taken at the
    worst of `-Xint`, C1 only and warm, in fresh agent-free JVMs, on 512 KiB, 1 MiB and a virtual
    thread.
  - A compile stores `D_f`, its deepest call-free nesting. A run derives
    `U_f = (stackBytes − reserve) / b − D_f` at its start.
  - In-suite tests run on a thread of at least 4× the declared `stackBytes`; the 512 KiB edges run
    only in fresh child JVMs.
  - F-30's "U may only fall" and the ADR-0018 re-run's "the release takes the smaller U" now read:
    a re-run may only raise `b` and the reserve.
  - ADR-0011 and ADR-0017 are amended.
