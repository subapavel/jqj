# F-1 — An untouched number cannot always be written from its original bytes

- **Assumption** (founding architecture §5 and §10; `docs/GATE.md` check 3): an untouched number
  is written from its original bytes, so a number literal round-trips byte for byte.
- **How it fails**: jq-ref 1.8.2 keeps a literal's precision but prints it canonically:
  `[1.10,3.00,1e2,-0,0.0,0.0000001]` → `[1.10,3.00,1E+2,-0,0.0,1E-7]`, `0.0000000` → `0E-7`,
  `1e1000` → `1E+1000` (observed by the grilling adviser on #5; `1e2` → `1E+2` also in the
  research note of #2).
- **Severity**: major (the gate's byte-identical output check depends on it).
- **Evidence**: issue #5 progress comment, round 2; `origin/research/jq-implementations`.
- **Change made**: ADR-0012 (issue #9). A CANONICAL token is copied byte for byte, and any other
  literal is rewritten to jq's canonical form, so there is no deviation. GATE check 3 now says
  "as jq prints them".
