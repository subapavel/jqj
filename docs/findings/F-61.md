# F-61 — `debug` and `stderr` are needed in spec 3a, not in specs 5 and 7

- **Assumption**:
  - ADR-0023 "Generator minimums": "The host-facing builtins arrive in specs 5 and 7 with
    hand-written cases". The glossary's Host-facing builtin lists `debug` and `stderr`.
  - ADR-0017 defines `DebugSink`; no ticket has built it.
- **How it fails**: spec 3 needs both before spec 5:
  - ADR-0022's pinned CE4 checks stderr `["DEBUG:",{"x":[1]}]`. Its retire rule fires on a value
    passed to `debug` or `stderr`, `gen/ownership-v1` draws `debug`, and `keptResultsNeverChange`
    snapshots through a `DebugSink`.
  - ADR-0010's SAME rule is pinned by `{"a":1} | path(.a|debug)` → `["a"]`.
  - jq-ref's L, R, L, R order on `[1,2]|(.[]|debug("L")) |= (debug("R")|.+1)` is how 3a shows that
    paths are not collected first.
- **Severity**: major (spec 3's gate-named tests cannot run).
- **Evidence**: spec 3 grilling round 1, A3; round 2, question 3.
- **Change made**:
  - `debug/0,1`, `stderr` and ADR-0017's `DebugSink` are 3a's third ticket (class B). They are
    covered from spec 4's gate (ADR-0023's spec-4 amendment).
  - ADR-0023's minimums bullet is amended.
  - GATE check 2 already reads "`debug/0,1` and `stderr` came in spec 3" (spec 4's records). The
    change of owner text is on the adviser's list for the owner (2026-11-16).
