# F-16: Clear-on-escape misses the owner reading its own state twice

- **Assumption** (founding §6.3, GLOSSARY "Ownership marker" and "Escape"): a value made inside
  `reduce`, `foreach`, `|=` or an array builder carries its operation's marker; the marker is
  cleared when the value escapes (bound to a variable, stored in another value, emitted), and while
  it matches the engine writes in place.
- **How it fails**: the owner itself can read the state twice without any escape.
  `reduce (1,2) as $x ([]; (. + [$x]), (. + [0]))` gives `[0,0]` on jq-ref 1.8.2; with
  clear-on-escape alone the second `+` sees the first one's append and gives `[0,2,0]`. A shallow
  freeze at each escape also fails: a copy of a frozen container still shares children that carry
  the live marker (ADR-0022, CE1–CE3). The array builder needs no marker at all, since nobody can
  see its partial value.
- **Severity**: major (a wrong value, not a slow one).
- **Evidence**: issue #8 round 1 (the record of the designer's draft and the adviser's evaluation,
  posted on #8); the jq-ref outputs are pinned as differential cases in ADR-0022.
- **Change made**: ADR-0022: a static in-place licence plus a per-activation owner that is retired
  when a value leaves the licensed chain. Founding §6.3 reads through ADR-0022; the glossary
  follows.
