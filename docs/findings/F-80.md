# F-80 — A state hold's detach leaves main-document views, so the view flag can stay set

- **Assumption**:
  - ADR-0022 "Detach and budgets": in a state hold that spans a later read, an in-place write
    detaches only the inserted value; "the state's view flag stays clear, so the hold's
    `detach()` is O(1) and keeps the owner (ADR-0007)".
  - Spec 5 round 2, question 1: a hold's detach copies only views of input documents; a
    main-document view passes, because the main document lives for the whole evaluation.
- **How it fails**:
  - With `. + [[$m.a, input]]` the inserted value keeps a view of the main document, so the
    state's view flag stays set and the next state hold would walk the whole state again.
  - Question 4(d) needs the flag clear; question 1 leaves it set. The two answers disagree.
- **Severity**: minor (no value is wrong; a step over such a state could walk it, which is
  quadratic over a reduce).
- **Evidence**: spec 5 grilling round 2, gap D (`docs/wayfinder/spec-5-grilling.md`, "Round 2"),
  proposed by the grilling-adviser for the owner under the delegation of 2026-11-14.
- **Change made**:
  - ADR-0022 "Detach and budgets", first bullet → "In a state hold that spans a later read, an
    in-place write detaches the inserted value's input-document views, and the state hold does
    not detach again a state the site wrote. The state's view flag stays clear only when the
    inserted value holds no main-document view."
  - ADR-0007's "Amendment (spec 5 round 2)": a state an in-place site wrote is not detached again
    at its state hold. S5b.2's `reduceInputStaysLinear` also runs with `[[$m.a, input]]`.
