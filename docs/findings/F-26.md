# F-26 — ADR-0015's "a missing continuation takes the bytes before it" is not jq's rule

- **Assumption** (ADR-0015, Strings and BOM): a missing continuation takes the bytes before it, so
  `e0 ff` at the end of a string would give two U+FFFD.
- **How it fails**: jq 1.8.2's `jvp_utf8_next` sets `length = end - in` when a sequence is cut by
  the end of the buffer, so the cut sequence takes every remaining byte; jq-ref records
  `i_string_truncated-utf-8` as `["�"]`, one U+FFFD.
- **Severity**: major for decoding (it binds `-R`, `fromjson`, `implode` and the spec-5 replay).
- **Evidence**: the designer's draft for #35 (conflict K1), 2026-11-12; `oracle/src/test/resources/json/json.rec`.
- **Change made**: ADR-0015 amended (#35). #35's recordings confirm the predicted rows.
