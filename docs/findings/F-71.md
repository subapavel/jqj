# F-71 — No exported pull for main documents, and `-n` is no input mode

- **Assumption**:
  - ADR-0016: "`jq-cli` opens them and reads the same `JsonInputs` through the exported API". Its
    reads are `read(MemorySegment)` and `Workspace.read(MemorySegment)`, one document each
    (ADR-0026). `InputOptions` carries `-n` among ADR-0015's input modes.
  - ADR-0015: "One input stream reader serves the command-line main loop and `input`/`inputs`."
- **How it fails**:
  - No exported method gives the main loop its next document from a `JsonInputs`. If jq-cli split
    the stream into segments, the main loop would run outside the parser state that `input` uses.
    Yet the two take turns on one stream: `[., input]` on `[1] [2] [3]` → `[[1],[2]]`, then
    "jq: error (at <stdin>:0): break", rc 5.
  - `-n` decides whether the main loop reads at all, while `input` still reads in every mode (P5:
    `-ns .` → `null`, `-ns [inputs]` → `[[1,2]]`).
- **Severity**: major (the command line cannot be built on the exported API).
- **Evidence**: spec 5 grilling round 1, question 1 (`docs/wayfinder/spec-5-grilling.md`); P5.
- **Change made**:
  - `JsonDoc Workspace.read(JsonInputs)` pulls the next main document and returns null at the end
    of the input stream. After a `JqSyntaxException` the `JsonInputs` can be read again. The
    command line then does what `main.c` does: stop with rc 5, or under `--seq` ignore and read on.
  - `-n` leaves `InputOptions`; the command line runs once on null. `JsonInputs` exports the
    current file name and line for `(at <file>:N)`.
  - ADR-0016 is amended, with question 9's withers (ADR-0024). On the adviser's list for the owner
    (2026-11-16).
